ECharts 方案 · 评分

幻觉风险高
视觉一致性中（依赖 LLM 配色）
外部依赖需 echarts.min.js (~900KB)
打印效果一般（Canvas 栅格化）
DOM 可访问性需 aria 标注
代码量多（配置对象 + JS）

CSS 方案 · 评分

幻觉风险零（无数据字段）
视觉一致性高（CSS 精确控制）
外部依赖零（纯 HTML/CSS）
打印效果优秀（DOM 原生打印）
DOM 可访问性优秀（节点全暴露）
代码量极少（CSS 属性声明）

核心实现对比

方案 A JS / JSON 配置 
// 需要额外加载 echarts.min.js (~900KB)
const chart = echarts.init(
  document.getElementById('chart-sunburst')
);

// ⚠️ LLM 幻觉高发区：填写精确 value 数值
// ⚠️ LLM 幻觉高发区：填写精确 radius 百分比
chart.setOption({
  type: 'sunburst',
  data: [{
    name: 'D1 方向与技术标尺',
    children: [{
      name: 'B1.1 主动问题识别',
      children: [
        { name: 'E1.1.1', value: 25 }, // ← 幻觉!
        { name: 'E1.1.2', value: 18 }  // ← 幻觉!
      ]
    }]
  }, { name: 'D2', children: [...] }],

  radius: ['15%', '90%'],    // ← 幻觉!
  label: { rotate: 'radial' }
});

// 还需要：canvas 导出、resize 监听、

结论

  • CSS 方案从架构上消灭了 LLM 填写精确数值的能力，从根本上规避数据幻觉
  • ECharts 方案的 value 字段是 LLM 幻觉重灾区，几乎无法完全约束
  • CSS 方案零外部依赖，文件更小，加载更快，无 CORS/网络依赖
  • ECharts 需要 ~900KB 的 js 文件，增加了报告分享复杂度
  • CSS 方案的 DOM 结构天然支持 SEO、屏幕阅读器、打印和 CSS 动画
  • Canvas 渲染的 ECharts 无 DOM 节点，需额外 aria 标注
  • CSS 方案配色精确可控，不会出现 LLM 随机选色导致的不一致
  • ECharts 在 LLM 生成时容易出现配色过亮/过暗/过饱和问题
