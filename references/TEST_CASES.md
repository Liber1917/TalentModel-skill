# 测试用例集

> 用于验证 Skill 输出的有效性

## 测试用例 1：技术专家评估

**类型**：社招 / 熟练型

```yaml
case_id: TC001
case_type: 技术专家评估

input:
  role: 后端架构师
  level: P8
  years_exp: 8
  background: |
    - 主导过电商核心支付系统重构
    - QPS 从 500 提升到 8000
    - 团队规模 5 人
    - 主导过数据库从 Oracle 到 PostgreSQL 的迁移

expected_output:
  layer_1:
    - 系统设计能力：能设计高可用分布式系统
    - 技术方案输出：能输出可执行的技术方案文档
    - 跨团队协作：能协调产品、测试、运维多方
  layer_2:
    - 技术视野：关注前沿技术趋势
    - 技术影响力：能培养初级工程师
    - 架构传承：能总结方法论并推广
  layer_3:
    - 追求卓越：对系统稳定性有执念
    - 长期主义：做技术决策时考虑长期维护成本
    - 风险意识：不会为短期收益牺牲系统健壮性

validation:
  - 每个能力项有至少 1 个行为证据
  - 没有雷达图
  - 没有使用麦克利兰等外部框架
```

## 测试用例 2：应届生潜力评估

**类型**：校招 / 潜力型

```yaml
case_id: TC002
case_type: 应届生潜力评估

input:
  role: 产品经理
  level: P5 (校招)
  years_exp: 0
  education: |
    - 985 计算机本科
    - GPA 3.7
    - 2段实习：某大厂实习、某创业公司实习

validation:
  - 禁止出现"5 年经验"等社招标准
  - 聚焦潜力型框架（学习力、适应性、成长型思维）
  - Layer 3 应聚焦可培养的特质
```

## 测试用例 3：管理晋升评估

**类型**：社招 / 管理型

```yaml
case_id: TC003
case_type: 管理晋升评估

input:
  role: 技术经理 (M1 → M2)
  current_level: M1
  target_level: M2
  years_exp: 6
  management_exp: 3
  background: |
    - 带过 5 人团队
    - 从零搭建过前端组
    - 主导过绩效考核体系改革

expected_output:
  layer_1:
    - 团队建设：能招聘、培养、保留人才
    - 目标管理：能拆解目标并追踪进度
    - 跨组协作：能协调多个团队的资源
  layer_2:
    - 战略对齐：理解业务战略并转化为技术目标
    - 组织影响力：能在部门层面推动变革
    - 人才培养体系：能建立可持续的人才梯队
  layer_3:
    - 成就他人：乐于看到团队成员成长
    - 灰度决策：在信息不完整时能做出判断
    - 全局视野：能跳出技术看业务

validation:
  - 管理能力有具体带团队的行为证据
  - 没有将"管理经验"等同于"技术深度"
```

## 测试用例 4：简历信息不足

**类型**：追问触发

```yaml
case_id: TC004
case_type: 信息不足触发追问

input:
  role: 产品经理
  description: "擅长沟通协调，有产品经验"

expected_behavior:
  - 拒绝直接输出胜任力模型
  - 触发追问流程
  - 要求提供：
    - 具体的沟通协调场景
    - 参与或主导的产品案例
    - 量化的工作成果

forbidden:
  - 不基于"擅长沟通协调"直接推断能力
  - 不使用预设的"沟通能力 L1-L5"标准
```

## 测试用例 6：校招社招隔离

```yaml
case_id: TC006
case_type: 校招社招污染检测

test_scenario: |
  当用户输入"应届生"时，检查模型中是否混入社招标准

forbidden_phrases:
  - "3 年以上管理经验"
  - "独立带过项目"
  - "有从 0 到 1 交付经验"（允许改为"有从 0 到 1 的学习项目经验"）
  - 任何要求 3 年以上经验的描述

validation:
  - 如果出现上述短语，校验引擎应报警
```
