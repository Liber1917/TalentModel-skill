# 测试用例2：前端开发实习生（校招大三/研二）

## 一句话画像

寻找**对前端技术有好奇心和学习热情、具备基础工程素养（Git/调试/协作）、能在大厂高并发场景下快速成长的潜力型候选人**。

---

## 一级胜任力维度（MECE）

| 维度 | 名称 | 核心定义 |
|------|------|----------|
| D1 | 方向与标尺 | 对"好前端"的理解——不仅功能正确，还关注体验、性能、代码组织 |
| D2 | 内驱与好奇 | 对前端技术自发的兴趣，以及主动探索新工具/新框架的倾向 |
| D3 | 学习敏捷 | 在新技术、新业务面前的上手速度和质量 |
| D4 | 基础工程素养 | Git、调试、浏览器原理、基础网络等前端工程基本功 |
| D5 | 协作准备度 | 在团队开发环境（code review、文档、协作流程）中的适应能力 |
| D6 | 韧性 | 在压力、模糊需求、快速迭代下的心理稳定性 |

---

## 各维度详细定义

### D1 方向与标尺
**定义**：实习生对"什么是好前端代码/好交互"的直觉判断，体现其对质量的内在线求。

**为什么重要**：校招/实习阶段重点看潜力，判断标准是否清晰决定了成长上限。

### D2 内驱与好奇
**定义**：不满足于"完成任务"，会自发探索"为什么这样做"、尝试新工具的倾向。

**为什么重要**：好奇心是技术成长的原动力，能主动探索的实习生成长更快。

### D3 学习敏捷
**定义**：面对新框架、新业务、新工具时，从陌生到能产出可用结果的效率。

**为什么重要**：前端技术迭代快，实习期又短，学习敏捷决定能否在有限时间内贡献价值。

### D4 基础工程素养
**定义**：Git 操作、浏览器 DevTools 使用、基础 HTTP 知识、命令行工具使用等。

**为什么重要**：这些是实习生的"生存工具"，直接影响能否顺利融入团队。

### D5 协作准备度
**定义**：在有 code review、文档要求、跨角色协作的团队环境中的适应能力。

**为什么重要**：大厂团队开发是协作而非单打独斗，协作意识决定能否顺利交付。

### D6 韧性
**定义**：在快速变化、需求调整、代码被 review 指出问题时的心态稳定性。

**为什么重要**：实习初期必然面临大量反馈，韧性决定能否将批评转化为成长。

## 可观察行为

### D1 方向与标尺
- 写代码时关注代码组织，不只是功能实现
- 对 UI/UX 有基本敏感度，能识别明显体验问题
- 会思考"为什么要这样写"，而非照搬示例代码

### D2 内驱与好奇
- 课余时间有尝试新技术/框架的经历（可验证）
- 主动阅读技术博客、参与前端社区活动
- 对团队的代码风格、工具选择有好奇心，会提问

### D3 学习敏捷
- 能清晰复述新学技术的核心概念（用自己的话）
- 第一个月的产出质量与学长学姐相近
- 能从错误中快速调整，不重复犯同类错误

### D4 基础工程素养
- 能独立用 Git 完成分支、提交、PR 流程
- 能用 DevTools 定位基本的前端问题
- 理解 HTTP 基本原理（GET/POST、状态码、缓存）

### D5 协作准备度
- PR 描述清晰，能说明改动目的
- 能接受 code review 意见，不会情绪化
- 主动向导师/同事提问（不是等别人来问）

### D6 韧性
- 第一次被要求大改代码时不崩溃，能理解原因
- 面对模糊需求时能主动确认，而非闷头实现
- 被指出低级错误时不推卸，能承认并学习

## 角色证据（验证点）

| 行为 | 典型证据 |
|------|----------|
| 技术好奇 | 技术博客/GitHub 项目、课外学习记录 |
| 学习敏捷 | 实习第一个月完成的任务难度和质量 |
| 基础素养 | 面试中的 Git/网络/浏览器问题表现 |
| 协作意识 | PR 质量、code review 接受度、提问频率 |
| 韧性 | 面对挫折（如 bug 久攻不下）时的应对方式 |

---

## 验证结论

**基于字节跳动、美团、网易前端实习招聘信息的交叉验证：**

1. ✅ **学习敏捷** — 各公司均强调"学习能力强"、"上手快"
2. ✅ **基础工程素养** — 字节/美团均要求"熟悉 HTML/CSS/JS"、Git 操作
3. ✅ **协作准备度** — 各公司均强调"良好的沟通能力"、"团队协作"
4. ⚠️ **方向与标尺** — 实习阶段不要求深度，主要看是否有"追求更好"的意识
5. **React/Vue/Webpack** 等具体技术栈 → 放入 D4 证据层，不作维度

## 适用边界

**适合用于：**
- 前端实习生的招聘筛选
- 大三/研二学生的实习申请评估
- 前端入门人才的潜力识别

**不适合用于：**
- 社招 1-3 年工程师（需补充独立承担模块的期望）
- 资深前端专家（需补充架构决策、性能优化维度）
- 纯设计方向（需替换工程维度为设计专业维度）
